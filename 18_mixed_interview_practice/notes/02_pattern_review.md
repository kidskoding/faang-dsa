# Pattern Review

## Pattern

After each problem, record the missed pattern or bug in the relevant module.

## Intuition

The goal is not just more problems; it is closing repeated gaps.

## How It Works

Keep a small review log of pattern, mistake, fix, and retry date.

## Template

```text
problem -> missed pattern -> cause -> corrected idea -> retry date
```

## Example

If you miss BFS level handling twice, reread graph/tree BFS notes before more problems.

## Complexity

```text
Review loop: 3-7 days
Space: one concise log entry per miss
```

## Pitfalls

- Doing new problems without reviewing misses.
- Writing vague notes like "I was dumb" instead of concrete bug cause.
- Not re-solving.

## Interview Checklist

Before coding, make sure you can answer:

```text
What pattern is this?
What state or invariant am I maintaining?
What is the base case or initialization?
When do I update the answer?
Why is the movement/transition valid?
What is the time and space complexity?
```
