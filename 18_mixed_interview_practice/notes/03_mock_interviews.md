# Mock Interviews

## Pattern

Mock interviews practice problem solving out loud.

## Intuition

You need to explain tradeoffs, assumptions, tests, and complexity while coding.

## How It Works

Use random mixed problems without topic labels.

## Template

```text
clarify
brute force
optimize
code
test
complexity
```

## Example

A good mock feels slower than solo LeetCode because communication is part of the task.

## Complexity

```text
One 45-60 minute mock
plus review
```

## Pitfalls

- Only practicing silent coding.
- Not testing edge cases aloud.
- Overexplaining after coding instead of during coding.

## Interview Checklist

Before coding, make sure you can answer:

```text
What pattern is this?
What state or invariant am I maintaining?
What is the base case or initialization?
When do I update the answer?
Why is the movement/transition valid?
What is the time and space complexity?
```
