# Mock Interviews

## Pattern

Mock interviews practice problem solving out loud.

## Intuition

You need to explain tradeoffs, assumptions, tests, and complexity while coding.

## How It Works

Use random mixed problems without topic labels.

## Template

```text
clarify
brute force
optimize
code
test
complexity
```

## Example

A good mock feels slower than solo LeetCode because communication is part of the task.

## Complexity

```text
One 45-60 minute mock
plus review
```

## Pitfalls

- Only practicing silent coding.
- Not testing edge cases aloud.
- Overexplaining after coding instead of during coding.

## Interview Checklist

Before coding, make sure you can answer:

```text
Have I clarified requirements out loud before proposing a brute force?
Am I narrating my optimization reasoning, not just typing silently?
Did I test edge cases aloud while coding, not after?
Is this problem unlabeled by topic, forcing real pattern recognition?
Have I stated complexity as part of the walkthrough, not an afterthought?
```
