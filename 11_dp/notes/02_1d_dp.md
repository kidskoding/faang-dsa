# 1D DP

**1D dynamic programming** is dynamic programming where a subproblem is named by
a single number. One index `i` walks along a line, `dp[i]` holds the answer to the
smaller version of the problem that stops at position `i`, and each new entry is
computed from a few entries already sitting behind it

You have already built an array with one number per index in
[prefix sums](../../01_arrays_and_hashing/notes/03_prefix_suffix_sums.md), and the
difference is worth being precise about. A prefix sum entry is a fixed aggregate
of the raw input, so `prefix[i]` is just the total of everything before `i` and
nothing about it involves a decision. A `dp[i]` entry is the *answer to a smaller
copy of the same problem*, and it is built by comparing the outcomes of the
choices available at position `i`, which is why the combine step is usually a
`max`, a `min`, or a sum over choices rather than a plain addition

The picture to hold is a single row of boxes being filled left to right, where
writing into box `i` only requires reading a couple of boxes immediately to its
left. Once that is true, the whole solution is one `for` loop

```text
dp   [ 2 ][ 7 ][ 11 ][ ? ][   ][   ]
                 \    ^
                  \___|   box i reads a fixed number of boxes behind it,
                          so one left-to-right pass fills the entire row
```

The "1D" describes the **state**, not the input. Delete and Earn hands you an
array and the useful line turns out to be the number line of possible *values*,
not the array itself, and that gap between the input and the axis you index is
most of the difficulty in this topic

## Why Robbing Every Other House Fails

[House Robber](https://leetcode.com/problems/house-robber/) is the problem this
whole topic is built around. Houses sit in a row, house `i` holds `nums[i]`
dollars, and robbing two adjacent houses on the same night sets off a shared alarm,
so no two chosen houses may be neighbours. Maximise the total taken

The tempting first idea is that "no two neighbours" sounds like every other house,
which leaves exactly two patterns to try, the even indices and the odd indices:

```python
def alternating_best(nums: list[int]) -> int:
    return max(sum(nums[0::2]), sum(nums[1::2]))


assert alternating_best([2, 7, 9, 3, 1]) == 12  # correct here, by luck
assert alternating_best([2, 1, 1, 2]) == 3  # the real answer is 4
assert alternating_best([]) == 0
```

The second assert is the whole lesson. On `[2, 1, 1, 2]` the even sum is `2 + 1 = 3`
and the odd sum is `1 + 2 = 3`, but robbing houses 0 and 3 gives `4` and breaks no
rule, because they are three apart. The optimal selection **skipped two houses in a
row**, and no fixed stride can express that

That failure is specific enough to hand you the fix. The constraint is not about a
pattern, it is a local decision made once per house: rob this one or leave it. What
does the decision at house `i` actually depend on? Only one thing, which is whether
house `i - 1` was robbed, and that in turn was decided by everything before it. So
carry forward the only two facts that any future decision can use:

- the best total achievable considering houses `0 .. i - 1`, which is what you keep
  if you skip house `i`
- the best total achievable considering houses `0 .. i - 2`, which is what house
  `i`'s money gets added to if you rob it, since robbing `i` forbids `i - 1` and
  forbids nothing earlier

Those two facts are `dp[i - 1]` and `dp[i - 2]`, so the recurrence writes itself:

```text
dp[i] = max(dp[i - 1], nums[i] + dp[i - 2])
         \_________/    \__________________/
          skip house i   rob house i
```

Everything else about the past, such as *which* houses were robbed to reach
`dp[i - 1]`, is irrelevant to the decision at `i`. That is the property that makes
one index a sufficient state

## Best Up To i Versus Best Ending At i

The two competing state sentences from
[DP fundamentals](01_dp_fundamentals.md) are the whole game once the state is a
single index, so they are worth restating in the vocabulary of a line. `dp[i]` can
carry one of two contracts, and picking the wrong one is the most common way a 1D
DP comes out subtly wrong. Decide which one you mean before writing a line of code,
because the base cases, the transition, and where the final answer lives all change

**Best up to i** means the answer over the prefix `0 .. i`, and element `i` is
allowed to be ignored. House Robber is this shape, since `dp[i] = max(dp[i-1], ...)`
explicitly permits skipping house `i`. For a maximisation problem this makes the
array non-decreasing, because a later prefix contains every option an earlier one
had, and the final answer is simply `dp[n - 1]`

**Best ending exactly at i** means the answer over selections that are *required*
to use element `i`. You need this whenever the thing being built has to be
contiguous, because a run that stops at `i` and a run that stops at `i - 1` are not
comparable unless they connect. The array is not monotone, so the final answer is
`max(dp)` over the whole array rather than the last entry

The test is one question. Can `dp[i]` describe a solution that does not touch
element `i`? If yes it is "up to", and if the problem forces element `i` to
participate then it is "ending at"

You have already written the second shape.
[Kadane's algorithm](../../01_arrays_and_hashing/notes/04_kadanes_algorithm.md) is
exactly a 1D DP whose state is "the best subarray sum ending at `i`", with the
transition `extend or restart` and a separate running global maximum, and the same
note handles Maximum Product Subarray by carrying a second ending-at-`i` value for
the minimum, since a negative flips the two. Both of those problems sit in this
module's ladder and need nothing new here beyond the vocabulary: they are 1D DP
with an ending-at-`i` state and rolling variables

```text
House Robber          dp[i] = best over houses 0..i         answer = dp[n-1]
Climbing Stairs       dp[i] = ways to reach step i          answer = dp[n]
Decode Ways           dp[i] = ways to decode first i chars  answer = dp[n]
Maximum Subarray      dp[i] = best sum ending at i          answer = max(dp)
```

## Filling The House Robber Table

Write the table version first, always, even if you already know it collapses to
two variables. A wrong recurrence in an `O(n)` table is easy to see and easy to
trace, and the same wrong recurrence hidden inside two rolling variables is not

```python
def rob(nums: list[int]) -> int:
    n = len(nums)
    if n == 0:
        return 0
    dp = [0] * n
    dp[0] = nums[0]
    for i in range(1, n):
        skip = dp[i - 1]
        take = nums[i] + (dp[i - 2] if i >= 2 else 0)
        dp[i] = max(skip, take)
    return dp[n - 1]


assert rob([1, 2, 3, 1]) == 4
assert rob([2, 7, 9, 3, 1]) == 12
assert rob([2, 1, 1, 2]) == 4
assert rob([5]) == 5
assert rob([]) == 0
```

**The three lines that decide whether this is right**:

- `dp[0] = nums[0]` is the base case, and it says that with one house available the
  best you can do is rob it, since `nums[i]` is non-negative in this problem. Setting
  it to `0` instead would quietly lose the single-house answer
- `dp[i - 2] if i >= 2 else 0` is the guard people leave out. Python treats `dp[-1]`
  as the last element of the list, so at `i == 1` an unguarded `dp[i - 2]` reads
  `dp[n - 1]` and raises nothing. Here that cell still holds the `0` the table was
  filled with, so dropping the guard happens to be harmless, which is exactly why
  the habit does not survive contact with other problems: prime the table with
  `float("-inf")` for a minimisation, or with a `1` for a counting problem, and the
  same silent wrap reads that value instead and returns a wrong answer with no
  error. Write the guard, and write `0` in it because "no houses at all" earns nothing
- `max(skip, take)` is the combine, and naming the two branches `skip` and `take`
  before comparing them is worth doing out loud, because the interviewer is
  listening for whether you can say what each branch means

The row for `[2, 7, 9, 3, 1]` fills like this, with the two arrows showing the two
candidates that `dp[2]` compares:

```text
i          0     1     2     3     4
nums       2     7     9     3     1
dp         2     7    11    11    12

                 |     ^
                 +-----+       skip house 2:  dp[2] <- dp[1]            = 7
           |           ^
           +-----------+       rob house 2:   dp[2] <- nums[2] + dp[0]  = 11
```

> "My state is `dp[i]`, the most money I can take from the first `i + 1` houses.
> Each house gives me two options, so I take the max of skipping it, which is
> `dp[i - 1]`, and robbing it, which is `nums[i] + dp[i - 2]`. The answer is the
> last entry, and I only ever look two positions back."

## Tracing Five Houses, Including The One Left Alone

Running the loop above on `[2, 7, 9, 3, 1]` gives one line per house, with both
candidates and which one won:

```text
i   nums[i]   skip = dp[i-1]   take = nums[i] + dp[i-2]   dp[i]   outcome
0      2            -                    -                  2     base case
1      7            2                    7                  7     rob house 1
2      9            7               9 + 2 = 11             11     rob house 2
3      3           11               3 + 7 = 10             11     REJECTED, skip house 3
4      1           11               1 + 11 = 12            12     rob house 4
```

Row `i = 3` is the one to study. House 3 holds real money and the algorithm refuses
it, because taking that `3` would have forced giving up the `9` from house 2, and
`3 + 7 = 10` is worse than the `11` already banked. Notice that nothing is undone
when this happens. The row simply copies `dp[2]` forward, which is what "skip"
means, and that copy is what lets house 4 add its `1` on top of a total that
already contains house 2

The final `12` corresponds to robbing houses 0, 2 and 4, and it beats the
alternating-sum answer only because row 3 was allowed to stall. A common wrong
version writes `dp[i] = max(dp[i - 1], nums[i] + dp[i - 2])` but then returns
`max(nums[i] + dp[i - 2] for i in ...)`, which is the "ending at `i`" answer to a
problem that has an "up to `i`" state

## Collapsing The Table Into Two Variables

The loop reads `dp[i - 1]` and `dp[i - 2]` and never touches anything older, so the
`n`-element array is `n - 2` entries of pure waste. Keep two integers instead:

```python
def rob_rolling(nums: list[int]) -> int:
    two_back = 0
    one_back = 0
    for value in nums:
        current = max(one_back, value + two_back)
        two_back = one_back
        one_back = current
    return one_back


assert rob_rolling([1, 2, 3, 1]) == 4
assert rob_rolling([2, 7, 9, 3, 1]) == 12
assert rob_rolling([2, 1, 1, 2]) == 4
assert rob_rolling([5]) == 5
assert rob_rolling([]) == 0
```

Both variables start at `0`, which represents an empty prefix, and that removes the
special case for `dp[0]` entirely, because the first iteration computes
`max(0, nums[0] + 0)` and lands on `nums[0]` by itself. It also makes the empty
input return `0` without a guard, since the loop body never runs

**The order of the two assignments is the bug that
[DP fundamentals](01_dp_fundamentals.md) sidestepped by writing the rolling update
as a single tuple assignment, and it is worth seeing once in the expanded form.**
`two_back = one_back` has to happen before `one_back = current`, otherwise
`two_back` receives the value just computed for this position instead of the
previous one, and every future decision reads a neighbour it was supposed to
exclude. Writing
`two_back, one_back = one_back, current` as a single tuple assignment sidesteps the
ordering question, since the right-hand side is evaluated before anything is bound

Space optimisation is legal exactly when the transition reads a **constant** number
of recent states. Two more conditions are worth checking before you do it:

- If the interviewer asks *which* houses were robbed, the two variables cannot
  answer, because reconstructing the choices needs the full table to walk backwards
  through. Offer the `O(n)` version in that case
- If a transition ever scans all earlier positions rather than a fixed few, rolling
  variables are impossible on their face, since there is no fixed set of values to
  roll

Do this second, never first. A collapsed loop with a wrong recurrence gives you
nothing to print and nothing to trace

## Counting Ways And Minimising Cost With The Same Skeleton

Climbing Stairs and Min Cost Climbing Stairs use the identical two-step lookback
and differ only in what they do with the two candidates. That is the general
picture: the lookback comes from the problem's rules about movement, and the
combine comes from the question being asked

```python
def climbing_stairs(n: int) -> int:
    dp = [0] * (n + 1)
    dp[0] = 1
    for i in range(1, n + 1):
        dp[i] = dp[i - 1] + (dp[i - 2] if i >= 2 else 0)
    return dp[n]


def min_cost_climbing_stairs(cost: list[int]) -> int:
    n = len(cost)
    dp = [0] * (n + 1)
    for i in range(2, n + 1):
        dp[i] = min(dp[i - 1] + cost[i - 1], dp[i - 2] + cost[i - 2])
    return dp[n]


assert climbing_stairs(2) == 2
assert climbing_stairs(3) == 3
assert climbing_stairs(1) == 1
assert climbing_stairs(0) == 1
assert min_cost_climbing_stairs([10, 15, 20]) == 15
assert min_cost_climbing_stairs([1, 100, 1, 1, 1, 100, 1, 1, 100, 1]) == 6
assert min_cost_climbing_stairs([5, 5]) == 5
```

`dp[0] = 1` in Climbing Stairs is the base case that looks wrong and is not. There
is exactly one way to be standing at the bottom of the staircase, which is to have
taken no steps, and that empty way has to count as one rather than zero, because
every route to step 2 is built by extending it. Setting `dp[0] = 0` makes the whole
array collapse to zeros, since a sum of zeros stays zero. Counting problems almost
always have an empty-solution base case of `1`, while maximisation problems have an
empty-solution base case of `0`

The two functions also show the other recurring indexing trap. Both tables have
`n + 1` entries rather than `n`, because the state is "reach position `i`" and
position `n` is the top of the staircase, one past the last stair you pay for. In
Min Cost Climbing Stairs `dp[0]` and `dp[1]` are both `0`, since the problem lets
you start on either of the first two stairs for free, and the cost of a stair is
charged when you *leave* it, which is why the transition reads `cost[i - 1]` and
`cost[i - 2]` rather than `cost[i]`

```text
problem                     dp[i] means                      combine   base
Climbing Stairs             ways to reach step i             sum       dp[0] = 1
Min Cost Climbing Stairs    cheapest way to reach step i      min      dp[0] = dp[1] = 0
House Robber                most money from houses 0..i       max      dp[0] = nums[0]
```

## When The Line Is Not The Input Array

[Delete and Earn](https://leetcode.com/problems/delete-and-earn/) gives you an
array of numbers. Picking the value `v` earns `v` points and deletes every copy of
`v` along with every copy of `v - 1` and `v + 1`. Maximise the points

Indexing the input array directly gets you nowhere, because the rule is about
values that happen to be adjacent numerically, and the array order is meaningless.
Change the axis. Lay the possible values out on the number line, and let
`points[v]` be the total earned by taking value `v`, which is `v` times how many
copies of it exist, since choosing `v` sweeps up all of them at once

On that line the rule becomes "you may not take two adjacent positions", which is
House Robber word for word:

```python
from collections import Counter


def delete_and_earn(nums: list[int]) -> int:
    if not nums:
        return 0
    counts = Counter(nums)
    points = [0] * (max(nums) + 1)
    for value, count in counts.items():
        points[value] = value * count
    return rob_rolling(points)


assert delete_and_earn([3, 4, 2]) == 6
assert delete_and_earn([2, 2, 3, 3, 3, 4]) == 9
assert delete_and_earn([1]) == 1
assert delete_and_earn([]) == 0
```

The gaps matter, and building the array over the *whole* value range rather than
over the distinct values present is what handles them. In `[3, 4, 2]` the points
line is `[0, 0, 2, 3, 4]`, so taking 2 and 4 is allowed and yields 6, while taking
3 and 4 is not. If you had compacted the distinct values into `[2, 3, 4]` and run
House Robber over those positions, a pair like 2 and 7, which are three apart in
value and adjacent after compaction, would be wrongly forbidden

> "The array order is irrelevant here, since the constraint is about numeric
> neighbours. I will bucket the input into a points array indexed by value, where
> `points[v] = v * count(v)`, and then the problem is House Robber on that line."

Recognising a solved 1D problem underneath a new one is worth more than any single
recurrence. The signal is a rule of the form "choosing `x` forbids the things
immediately beside `x`", once you have found the axis that "beside" is measured on

## Robbing Houses Arranged In A Circle

[House Robber II](https://leetcode.com/problems/house-robber-ii/) puts the same
houses in a ring, so house `0` and house `n - 1` are now neighbours. The instinct is
to bolt a wrap-around case onto the recurrence, and that fails because whether
house `n - 1` is allowed depends on a decision made at the very start of the loop,
which a left-to-right pass has already forgotten

The clean move is to remove the circularity by case-splitting on the one pair that
causes it. Houses `0` and `n - 1` cannot both be robbed, so every valid selection
either leaves out house `0` or leaves out house `n - 1`, and possibly both. Run the
linear solver on each of those two lines and take the better result:

```python
def rob_ii(nums: list[int]) -> int:
    if len(nums) == 1:
        return nums[0]
    return max(rob_rolling(nums[:-1]), rob_rolling(nums[1:]))


assert rob_ii([2, 3, 2]) == 3
assert rob_ii([1, 2, 3, 1]) == 4
assert rob_ii([1, 2, 3]) == 3
assert rob_ii([5]) == 5
```

Neither run misses an answer and neither invents one. Every legal ring selection
appears in at least one of the two windows, because it must omit one of the two
ends, and every selection found inside a window is legal on the ring, because a
window is a plain line whose two ends are not adjacent to each other in it. The
`len(nums) == 1` guard exists because `nums[:-1]` is empty for a single house, and
`nums[1:]` is too, so both runs return `0` and the lone house is lost

## Worked Example: [Decode Ways](https://leetcode.com/problems/decode-ways/)

A message was encoded by mapping `'A'` to `"1"`, `'B'` to `"2"`, and so on through
`'Z'` to `"26"`, then concatenating the numbers with no separators. Given the digit
string, count how many different original messages could have produced it, so
`"12"` could be `"AB"` from `1, 2` or `"L"` from `12`

**Input**: `s`, a `str` of length `1 <= len(s) <= 100` containing only the
characters `'0'` through `'9'`. Leading zeroes are possible, and a zero is never a
valid code on its own since the mapping starts at 1

**Output**: an `int`, the number of distinct ways to split `s` into pieces that are
each a valid code from `"1"` to `"26"`. It is `0` when no valid split exists at
all, which is a legitimate answer rather than an error, and it counts the splits
themselves, so two different splits producing different letters are two ways

"Count the number of ways" plus "each step consumes one or two characters" is the
same shape as Climbing Stairs, so the state is a prefix length and the lookback is
two. The naive version recurses at every position, branching into "take one digit"
and "take two digits", which is exponential and re-decodes the same suffix once for
every path that reaches it. Since the number of ways to decode the first `i`
characters does not depend on how those characters were reached, one entry per
prefix length is enough

> "I will define `dp[i]` as the number of ways to decode the first `i` characters,
> with `dp[0] = 1` for the empty prefix. Each character can be decoded alone if it
> is not `'0'`, and paired with the one before it if that pair reads between 10 and
> 26, so `dp[i]` is the sum of whichever of those two moves is legal."

1. Let `dp[i]` be the number of ways to decode the first `i` characters, so the
   index counts characters consumed rather than a position in the string. That makes
   the table `n + 1` long and the answer `dp[n]`, and it gives the two-character move
   somewhere to land when it reaches back past the start
2. Set `dp[0] = 1`, meaning the empty prefix has exactly one decoding, which is the
   empty message. This is the counting base case, and setting it to `0` zeroes the
   entire table because every later entry is a sum of earlier ones
3. For each prefix length `i` from 1 to `n`, start `dp[i]` at zero and consider the
   two ways the message could end, adding the count of each legal one. The two moves
   are independent, so the combine is a sum rather than a max
4. The one-character move takes `s[i - 1]` as a letter by itself. It is legal only
   when that character is not `'0'`, because no letter maps to 0, and when it is
   legal it contributes `dp[i - 1]`, since every decoding of the shorter prefix
   extends by this single letter in exactly one way
5. The two-character move takes `s[i - 2 : i]` as one letter. It is legal only when
   `i >= 2`, so there are two characters to take, and when the pair reads between 10
   and 26 inclusive. The lower bound of 10 is what rejects `"01"` and `"08"`, since
   a code with a leading zero was never produced by the encoder. When legal it
   contributes `dp[i - 2]`
6. If neither move is legal, `dp[i]` stays `0`, and that zero then propagates
   forward through every later sum, which is how an undecodable string like `"06"`
   correctly reports `0` without any special handling
7. Return `dp[n]`, the number of decodings of the whole string

```python
def num_decodings(s: str) -> int:
    n = len(s)
    dp = [0] * (n + 1)
    dp[0] = 1
    for i in range(1, n + 1):
        if s[i - 1] != "0":
            dp[i] += dp[i - 1]
        if i >= 2 and 10 <= int(s[i - 2 : i]) <= 26:
            dp[i] += dp[i - 2]
    return dp[n]


assert num_decodings("12") == 2
assert num_decodings("226") == 3
assert num_decodings("06") == 0
assert num_decodings("2101") == 1
assert num_decodings("0") == 0
assert num_decodings("100") == 0
```

Tracing `"2101"` shows both rejections, with each row listing what the two moves
contributed:

```text
i   char   one-digit move        two-digit move          dp[i]
0    -     -                     -                        1     base case, empty prefix
1   '2'    '2' ok,     += dp[0]  no pair yet                1
2   '1'    '1' ok,     += dp[1]  "21" ok,     += dp[0]      2
3   '0'    '0' REJECTED, adds 0  "10" ok,     += dp[1]      1
4   '1'    '1' ok,     += dp[3]  "01" REJECTED, adds 0      1
```

Row 3 is where the zero earns its rule. The character `'0'` contributes nothing on
its own, so the only surviving decoding of `"210"` is the one that reads `"10"` as
`'J'`, and the count drops from 2 to 1. Row 4 then refuses the pair `"01"` for the
same underlying reason, which is that `01` is not a code the encoder could have
emitted, so the final `1` corresponds to the single reading `B, J, A`

- **Time Complexity:** `O(n)` for a string of length `n`, because the loop runs once
  per prefix length and each iteration does two constant-time checks, with
  `int(s[i - 2 : i])` parsing a slice of fixed width 2
- **Space Complexity:** `O(n)` for the table, which collapses to `O(1)` by keeping
  only `dp[i - 1]` and `dp[i - 2]` in two variables, since no entry older than two
  positions is ever read again

## Time and Space Complexity

Throughout, `n` is the number of positions on the line the state indexes, meaning
houses, stairs, or characters depending on the problem

**House Robber, and the shape every problem in this topic shares**

| Approach                                                  | Time                                                                                                 | Space                                                                                                     |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Rolling variables                                         | `O(n)`: one pass with a comparison and two assignments per position                                  | `O(1)`: two integers, neither of which grows with the input                                               |
| Full `dp` array                                           | `O(n)`: the same single pass, with one table write per position                                      | `O(n)`: one entry per position, which is what you must keep if asked to report *which* houses were robbed |
| Recursion with no memo, branching take/skip at each house | `O(2^n)`: nothing is remembered, so the same suffix is re-solved once for every path that reaches it | `O(n)`: the call stack holds one frame per house along the current branch                                 |

**The rest of the module's 1D ladder**

| Problem                                    | Time                                                                                                                     | Space                                                                                                                              |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| Climbing Stairs, Min Cost Climbing Stairs  | `O(n)`: one pass over `n` steps doing constant work each                                                                 | `O(n)` for the table, or `O(1)` with two rolling variables, since the lookback is fixed at two                                     |
| Decode Ways                                | `O(n)`: one pass over the string, with a fixed-width two-character check per position                                    | `O(n)` for the table, or `O(1)` rolling, because no entry older than two is read again                                             |
| House Robber II                            | `O(n)`: two linear passes, each over `n - 1` houses                                                                      | `O(n)`: the two slices `nums[:-1]` and `nums[1:]` each copy the array, and passing index bounds instead brings this down to `O(1)` |
| Delete and Earn                            | `O(n + M)`: `O(n)` to count the values plus `O(M)` to sweep the points line, where `M` is the largest value in the input | `O(M)`: the points array spans the whole value range, so a small array holding one huge value still allocates `M` slots            |
| Maximum Subarray, Maximum Product Subarray | `O(n)`: one pass, covered in [Kadane's algorithm](../../01_arrays_and_hashing/notes/04_kadanes_algorithm.md)             | `O(1)`: an ending-at-`i` value plus a running global best, and a second extreme for the product version                            |

Delete and Earn is the row worth remembering, because it is the only one whose cost
is not governed by the input length. An input of three numbers whose maximum is a
million allocates a million slots, and the fix, if pressed, is to sort the distinct
values and run the recurrence over them while checking whether consecutive entries
actually differ by 1

## Summary

- **1D dynamic programming** names each subproblem with a single index into a line,
  so `dp[i]` is the answer to the version of the problem that stops at position `i`,
  and each entry is computed from a fixed number of entries just behind it. The
  entire solution is one left-to-right loop
  - It differs from a prefix-sum array, which stores a fixed aggregate of the raw
    input, because a `dp` entry is the result of comparing the outcomes of the
    choices available at that position
  - The "1D" describes the state and not the input, and Delete and Earn is the
    reminder, since its line is the number line of values rather than the given array
- The signal for this pattern is a sequence of positions where a decision at
  position `i` is constrained only by decisions a fixed distance back, as in
  "no two adjacent", "take one or two steps", or "consume one or two characters"
  - The naive idea that fails is assuming the optimal choices follow a fixed
    pattern, such as robbing every other house. On `[2, 1, 1, 2]` the optimum skips
    two houses in a row and takes 4, while both alternating sums give 3
- Decide what `dp[i]` means before writing code, because the whole solution follows
  from it. **Best up to `i`** allows ignoring element `i`, so the answer is
  `dp[n - 1]`, and **best ending exactly at `i`** requires using element `i`, so the
  answer is `max(dp)` over the array
  - The test is whether `dp[i]` can describe a solution that does not touch element
    `i`. Problems needing a contiguous run, such as Maximum Subarray, force the
    ending-at-`i` contract
  - Reading the answer off the last entry when the state is "ending at `i`" is a
    standard wrong version, and so is scanning for a maximum when the state is
    "up to `i`"
- The House Robber recurrence is `dp[i] = max(dp[i - 1], nums[i] + dp[i - 2])`,
  where the first branch skips house `i` and the second robs it and therefore has to
  reach back past its forbidden neighbour
  - Climbing Stairs is the same two-step lookback with `+` instead of `max`, and
    Min Cost Climbing Stairs is the same again with `min`, so the lookback comes
    from the movement rules and the combine comes from the question
  - Guard the reach-back explicitly, since Python reads a negative index as a
    position from the end of the list rather than raising. A zero-filled
    maximisation table forgives the omission, and a table primed with `1` or
    `float("-inf")` returns a wrong answer with no error at all
- Counting problems take an empty-solution base case of `1` and maximisation
  problems take `0`, because one empty decoding exists and must be extendable,
  whereas an empty selection earns nothing
  - `dp[0] = 0` in a counting problem zeroes the entire table, since every later
    entry is a sum of earlier ones
  - Tables for "reach position `i`" problems hold `n + 1` entries, because position
    `n` is the top of the staircase or the whole string consumed
- Space collapses from `O(n)` to `O(1)` whenever the transition reads only a
  constant number of recent states, by keeping `one_back` and `two_back` instead of
  the array
  - Assign `two_back` before `one_back`, or use a tuple assignment, because the
    other order feeds the current position's answer back in as its own neighbour
  - Do this only after the table version is correct, and offer the table when the
    interviewer asks which elements were chosen, since reconstruction needs the
    full row to walk backwards through
- Two reductions cover most of the disguised versions in this module. **Delete and
  Earn** re-indexes the input onto a points line over values, where `points[v]` is
  `v` times its count, and then it is literally House Robber. **House Robber II**
  removes a circular constraint by running the linear solver twice, once without the
  first house and once without the last, and taking the better result
  - Build the points line over the full value range rather than over the distinct
    values, because compacting makes values three apart look adjacent
  - The two-run split is exhaustive because houses `0` and `n - 1` cannot both be
    taken, so every valid ring selection omits at least one of them
- The cost of a 1D DP is the number of states multiplied by the work per transition,
  which here is `O(n)` time with `O(1)` work per position, and `O(n)` space that
  usually reduces to `O(1)`
  - Delete and Earn is the exception, at `O(n + M)` time and `O(M)` space for a
    largest value `M`, so a three-element input containing one huge number still
    allocates a huge array

## Interview Checklist

Before writing code, make sure you can answer each of these

```text
Can I say what dp[i] means in one sentence, without using the word "dp"?
Is it best UP TO i, which may ignore element i, or best ENDING AT i, which must use it?
Given that, is the answer dp[n-1], dp[n], or max(dp) over the whole array?
Is my table n long or n+1 long, and does index i mean a position or a count consumed?
Which earlier indices does the transition read, and is every reach-back guarded at i < 2?
Is the combine a max, a min, or a sum, and does that match what the problem asks for?
Is the base case 1 because I am counting, or 0 because I am maximising?
Does an impossible position stay 0 and propagate, or does it need an explicit block?
Is the line I am indexing the input array, or a derived axis like the value number line?
Can I collapse to two variables, and if so am I assigning two_back before one_back?
If asked which elements were chosen, do I still have the table needed to reconstruct?
```
